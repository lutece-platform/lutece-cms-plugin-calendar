# Plugin calendar

## Introduction

This plugin publishes events on calendars (agendas) of a Lutece site. Webmasters create the calendars and their events in the back office; visitors browse them in the front office by month, week, day or as a list, search them, subscribe to them and add them to their own calendar application.

It can be used together with [module-calendar-document](../module-calendar-document/) or [module-documenttocalendar](../module-documenttocalendar/).

## Features

* Calendars with a name, a colour, a role and a workgroup, an optional e-mail notification and a period for it.
* Events with dates, times, description, location, categories, image, URL, status (confirmed, tentative, cancelled) and occurrences (repeated by day, week or month, with excluded days).
* Front-office views built with [EventCalendar](https://github.com/vkurko/calendar) (MIT): month, week, day and list, filters by calendar and category, responsive (list view on small screens). Without JavaScript, a text list of the events is shown.
* A back-office calendar view: a click on a day creates an event on that day, an event is moved or resized by drag and drop (one occurrence or the whole series).
* An "Add to calendar" button on the page of an event (Google, Outlook.com, Microsoft 365, Teams, Yahoo, Apple, iCal file), set for each calendar in the back office.
* Exports: iCalendar (.ics, also as a subscription link for the calendars open to everybody), JSON, and an RSS 2.0 feed of the events.
* Subscription to a calendar by e-mail, with reminders sent before each occurrence by the daemon calendarReminder.
* Two portlets: a calendar portlet listing the events of selected calendars, and a mini calendar of the month.
* Full-text search of the events through the core Lucene indexer, an insert service to put a link to an event in a rich text editor, and back-office dashboard widgets.

# Configuration

## Rights

The admin feature `CALENDAR_MANAGEMENT` (menu "Calendar management") gives access to the calendars, the calendar view, the "Add to calendar" button options and the categories. The installation script grants it to the `admin` user. The calendars are also RBAC resources (type `CALENDAR`, permission `MANAGE`) and are filtered by workgroup.

## Exports

* `jsp/site/plugins/calendar/CalendarIcal.jsp?calendar_id=N`: iCalendar feed of a calendar (from `calendar.ical.feed.daysBefore` days before today to `calendar.ical.feed.daysAfter` days after), or of one occurrence with `occurrence_id=N`.
* `jsp/site/plugins/calendar/GetCalendarFile.jsp?calendar_id=N&format=json`: JSON file of a calendar.
* `jsp/site/plugins/calendar/GetCalendarFile.jsp?action=rss&calendar_id=N`: RSS 2.0 feed (at most `calendar.rss.maxItems` items).

A calendar restricted to a role is exported only to a visitor logged in with that role. The exports are not managed in the back office.

## Reminders

The daemon `calendarReminder` is off by default: start it in the daemons screen of the back office. It sends to the subscribers of a calendar a reminder of each occurrence starting within `calendar.reminder.hoursBefore` hours (24 by default), once per subscriber. The links of the e-mails use `lutece.prod.url`, or `lutece.base.url`: one of them must be set.

## Portlet templates

The portlets are rendered by FreeMarker templates registered in the core portlet templates, chosen in the portlet form:

* `CALENDAR_PORTLET`: `skin/plugins/calendar/portlet/calendar_portlet.html` (default) and `calendar_portlet_organized_events.html`.
* `MINI_CALENDAR_PORTLET`: `skin/plugins/calendar/portlet/mini_calendar_portlet.html`.

# Upgrading to Lutece 8

Version 5.0.0 requires Lutece core 8 (CDI, Jakarta EE, Liquibase). The script `upgrade/update_db_calendar-4.9.9-5.0.0.sql`:

* replaces the XSL styles of the portlets by the FreeMarker templates above;
* converts the dot image of each calendar into its colour (`.../dots/blue.png` becomes `blue`);
* removes the XSL export stylesheets (`calendar_export_stylesheets`): the exports are iCalendar, JSON and RSS;
* creates the tables of the reminders and of the "Add to calendar" button.

The v7 SQL scripts carry no Liquibase header, so a v7 database records no version for the plugin: the site must be taken over in two passes (version of the plugin recorded first, then start), otherwise the plugin is installed as new and the upgrade script does not run. The former export links (`GetCalendarFile.jsp`) keep working: they now answer the iCalendar file of the calendar, or its RSS feed.
